# 功能清单与范围

目前完成了一部分底层逻辑，实际 App 功能还没有接通。逐项查看 [已做什么、模拟器测过什么、还缺什么](mvp-status.md#目前的功能)。

## 第一版功能

| 功能 | 当前状态 |
|---|---|
| 手机登录连接 | 部分实现：登录状态、刷新逻辑已做，实际登录未接通 |
| 手表消息／待办列表 | 部分实现：列表筛选、排序逻辑已做，手表页面未接通 |
| 快捷文本回复 | 部分实现：候选过滤和规则回复已做，实际生成与发送未接通 |
| 常用回复卡片 | 未实现：只有数据字段，没有编辑或同步功能 |
| 系统听写回复 | 未实现：只有消息来源标记，未接系统听写 |
| 确认按钮／选项／简单表单 | 部分实现：选项和字段校验已做，实际按钮与提交未接通 |
| 手机手表通信 | 部分实现：消息格式和收发流程已做，真实双端通信未接通 |
| 断线重试与防重复 | 部分实现：操作编号、重试条件和去重已做，真实断线流程未接通 |
| 登出清理 | 部分实现：本机清理及旧操作失效逻辑已做，App 登出与双端清理未接通 |
| 语音开始／结束／静音与手机麦克风通话 | 未实现：尚无语音会话与通话控制 |
| 真机安装 | 部分实现：工程和安装说明已准备 |

这些底层逻辑已有替身数据的单元测试，但不能当作 App 功能实测。已有项目报告启动过双端模拟器文字骨架，原始截图未独立核验；各功能尚未做模拟器交互实测。

## 接下来怎么做

建议先打通手机登录和消息，再接手表列表、回复和确认，补齐卡片与听写，完成手机麦克风通话和手表开关，最后做完整真机及异常场景验证。语音开发前先验证原规格要求的锁屏／挂起发起能力。

具体交付内容和操作验证方式见 [短路线图](mvp-status.md#建议后续顺序)；这是建议顺序，尚不是已批准实施计划。常用卡片、听写和手机麦克风通话都保留在第一版。

## 以后再做

- 录音后转写成文字。
- 自动麦克风路由，以及手表麦克风中转和直连。
- 手表独立登录、通过 HTTPS 直连的降级方式。
- 表盘入口和本地可操作通知。
- 其他候选生成后端（如 xAI）及离线候选缓存优化。

常用卡片、系统听写和手机麦克风语音都仍在第一版内；以上才是原规格的后续范围。完整要求见 [原规格](spec.md)。

## MVP 状态矩阵

此处保留原链接锚点；面向使用者的状态以 [主功能表](mvp-status.md#目前的功能) 为准。需求和验收阈值仍以 [spec v0.2](spec.md) 为准。

| 原编号 | 对应功能与范围 |
|---|---|
| B1 | 手机登录连接、本机登出清理；第一版 |
| B2 | 真实消息与私有接口读写、回复和确认的服务连接；第一版 |
| B3 | 手机手表通信、结果送达、重试防重复和双端清理；第一版 |
| F1 | 确认按钮、选项与简单表单；第一版 |
| F2 | 快捷文本候选与回复；第一版 |
| F3 | 常用回复卡片；第一版 |
| F4 | 系统听写回复；第一版 |
| F5 | 手机麦克风通话，手表开始／结束／静音与字幕；第一版，S-3 为前置闸门 |
| F8 | 手表消息与待办列表；第一版 |
| F4+ | 录音后转写；后续 |
| F6 | 自动麦克风路由、手表麦克风中转／直连；后续 |
| F7 | 手表独立登录与 HTTPS 降级；后续 |
| F8+ | 表盘入口／本地可操作通知；后续 |

S-3 仍按 [原矩阵](spec.md#7-验证项spike结论写回-design) 决定采用手表发起还是手机发起，不改变全部公共语音要求。后续生成后端和离线候选缓存优化的范围也保持不变。

验证证据和未完成登记见 [技术参考](mvp-status.md#验证层级) 与 [剩余事项](mvp-status.md#剩余事项)，CI 的运行与历史记录见 [ci.md](ci.md)。
