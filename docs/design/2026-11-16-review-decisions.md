# 2026-11-16 首轮设计评审后的决定

背景：spec v0 首轮只读设计评审（Claude Code）结论为"有条件通过"，S1=0，S2=9（其中 3 项阻断主流程），S3=13。负责人随后做了以下决定。

## 决定

1. **隐私扫描命中**：首轮推送前扫描有 11 处命中，全部来自模板规则原文里的关键词（8 处）和 xAI 官方实时语音文档里的协议名（3 处），不是真实敏感信息。负责人逐条放行这 11 处，不加 allow-list 条目；以后出现任何新命中仍要停下来报告。
2. **3 项阻断 S2 在本轮修 spec 后复评**：
   - 防重复：按操作类型（发消息、确认答复、表单、语音开关）分别定规则，写清手动重试与后端去重的配合（architecture §5.1）。
   - 结果丢失：手表持久发件箱；iPhone 先落盘请求再发网络写；服务器请求 ID 由手表操作 ID 派生；最终结果经 `transferUserInfo` 回传（architecture §5.2）。
   - F5 门槛：把"手机锁屏时能否从手表发起 iPhone 后台录音"列为必须先做的验证项 S-3；不通过就改为"手机发起、手表控制"（spec §5 F5、§7，architecture §11）。
3. **签名**：没有付费 Apple 开发者会员，先用免费 Personal Team 侧载。签名 7 天过期要重签，App ID 和能力有限制；依赖付费会员的能力（远程推送、PushKit、受管 entitlement 等）不可用，影响逐项列在 spec §10。
4. **构建环境**：watchOS/iOS target 的构建和真机调试在负责人的 Mac 笔记本上进行；本轮不接 macOS CI。

## 未在本轮处理

首轮评审中不阻断的 S2（麦克风路由状态机、语音会话协议约束、F1 范围细节、F2/F8 新鲜度、扫描清单位置、提交署名格式）和 S3 建议登记到下一轮。
