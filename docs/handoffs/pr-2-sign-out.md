# PR #2 登出清理与下轮登记

来源为 PR #2 独立评审终稿，评审 head 为 `6a91cf5b37e3b4d3846db1ab7869cfdfbad26108`。本轮修复从 `23ec6451c6b663ef2f5016139548770035e9eb9e` 开始，该提交相对评审 head 只含 README 和截图更新。

## 本轮范围

S2-3 覆盖本地登出。配套 app 的登出回调调用本机 `PhoneRelay.purge()`，手表端通过 `WatchOutbox.purge()` 清除手表上的发件箱。两个 actor 以原子空快照清除持久记录并更新内存，旧异步操作恢复时按清理前的代次失效。已经交给通道的发布完成后，手机的清理才返回。清理报错时需要先重试登出，再开始新授权。

跨设备传播登出状态、清空顺序，以及通道中已经排队的旧消息如何处理，留给适配器接入时验证。

## 下轮

以下各项沿用同一份独立评审终稿和评审 head。

- **S2-1（不阻断）** 确认预检把瞬时网络失败归为协议失效，手表显示终态拒绝且不能重试。接入真实 F1 传输前修复。
- **S2-2（不阻断）** 快照超过 64 KiB 时整份无法发送，`recentOps` 备用通道也受影响。补充规格并明确裁剪责任。
- **S3-1** 完善 `receiveMessage` 对 `inbox.refresh` 等非写消息、准入前拒绝的回执，以及 Bot 查不到时的处理。
- **S3-2** 明确发布失败后的补发机制。当前只能依赖快照中最近 20 条结果。
- **S3-3** 验证未终态记录的 7 天保留期、设备间时钟偏差，以及手表发件箱的常态清理。
- **S3-4** 规格补充确认预检的读请求会增加 ack 延迟。
- **S3-5** 验证 gateway 按原文对账前是否需要统一文本形式。
- **S3-6** 验证重试是否需要保留固定首次发送时间，决定是否在 `WriteAttempt` 记录时间戳。
- **S3-7** 写明传输适配器映射契约并核实服务端 roster 和 approval RPC 名称。
- **S3-8** 补充旧版本识别和去内容的协议诊断。
- **S3-9** 收紧 `SessionToken` 默认描述，补轮询截止时间与登录会话标识，并记录离线刷新需要重新登录的取舍。
- **S3-10** 核对 widget 候选的 label、value 和数量规则，修订与 2–4 条规格不一致的测试。
- **S3-11** 确定存储文件保护等级及备份排除策略。
